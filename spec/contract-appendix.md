## 1. Profile digest

### 1.1 Normalized effective profile

A profile is normalized before anything else looks at it:

| Member | Rule |
| --- | --- |
| name | `^[a-z0-9][a-z0-9._-]{0,62}$`; the catalog key; **not** digested |
| `kind` | `external-http-proxy` or `direct` |
| `endpoint` | forbidden on direct, even empty; for external-http-proxy, `http://host:port`: scheme `http`, explicit numeric port 1–65535, no userinfo, no path but `/`, no query, no fragment; scheme and host lowercased, IP literals canonicalized with `netip`, IPv4-mapped IPv6 unmapped to IPv4, IPv6 host in brackets, trailing `/` dropped |
| `bypass_hosts` | forbidden on direct, even empty; for external-http-proxy, each entry trimmed and lowercased; deduplicated; sorted in byte order; MUST contain `127.0.0.1`, `::1`, `localhost`; an empty entry, `*`, a comma or whitespace inside an entry, or a character outside `[a-z0-9._:[]/-]` is refused |
| `credential_mode` | `none` (the only mode of this version; a credential in the endpoint is refused without being echoed) |
| `probe_target` | forbidden on direct, even empty; for external-http-proxy, optional `host:port`; **not** digested |

For a proxy profile the digest covers exactly `schema`, `kind`, `endpoint`, `bypass_hosts` and
`credential_mode`. For direct it covers only `schema`, `kind` and `credential_mode`. It MUST NOT cover the name, `probe_target`, probe results,
timestamps, lease ids or generations. A digest binds the configuration, not
the proxy's actual egress.

### 1.2 Canonical form

For a proxy profile the digest input is one JSON object with these five keys in byte order and no
other key, no whitespace, UTF-8, no HTML escaping, strings escaped as RFC 8259
requires:

```text
{"bypass_hosts":[<sorted entries>],"credential_mode":"none","endpoint":"<endpoint>","kind":"external-http-proxy","schema":"relux-network-profiles-v1"}
```

Direct has exactly these three keys, in byte order:

```text
{"credential_mode":"none","kind":"direct","schema":"relux-network-profiles-v1"}
```

Adding or changing any profile, including direct, is a widening (it reroutes traffic) and MUST require `curator network confirm` at the current digest.

### 1.3 Algorithm

```text
profile_digest = "sha256:" + lowercase-hex( SHA-256( canonical bytes ) )
```

## 2. EnvPatch

A patch is two ordered operations, `unset` then `set`, applied by the host
that creates the process to that process's private environment. It is never
only additions. `Apply` MUST NOT call `os.Setenv`, MUST NOT read the process
environment and MUST NOT modify its input; it returns a new slice.

### 2.1 Adapter `generic-env-v1`

`unset` lists the reserved proxy family in both canonical spellings; `Apply`
removes every inherited entry whose *name* equals one of them
case-insensitively (so `Http_Proxy` is removed too):

```text
HTTP_PROXY HTTPS_PROXY ALL_PROXY FTP_PROXY NO_PROXY
http_proxy https_proxy all_proxy ftp_proxy no_proxy
```

`set` for a proxy profile is appended in this fixed order:

```text
HTTP_PROXY=<endpoint>   HTTPS_PROXY=<endpoint>
http_proxy=<endpoint>   https_proxy=<endpoint>
NO_PROXY=<bypass_hosts joined by ",">   no_proxy=<the same>
```

`ALL_PROXY`, websocket-specific variables and runtime settings are NOT set by
the generic adapter; only a verified harness adapter adds them (spec N5). A
harness adapter reports its own identity string in `adapter_identity.adapter`.

For direct, `unset` is the identical list above and `set` is an empty array. No inherited proxy-family variable survives, and nothing is added.

### 2.2 Apply semantics

1. Walk the inherited entries in order. An entry `NAME=VALUE` is dropped when
   `NAME` equals an `unset` name case-insensitively or a `set` name exactly.
   An entry without `=` has no name and is kept as it is. All other entries
   are kept in their original order.
2. Append the `set` pairs in order.

Consequences: a `set` name cannot survive twice; applying the patch to an
already patched environment changes nothing (idempotence); case conflicts,
an ambient `NO_PROXY=*` and a conflicting variable present only on the host
never reach the child.

### 2.3 Unmanaged

No selection at all yields the empty patch: `unset` and `set` are empty and
`Apply` returns the environment unchanged. The launch is reported as
`unmanaged`, never as "direct".

### 2.4 Transport

`Patch.SetLiterals()` is the `set` half as name/value pairs: what a tracked
transport carries as owned literals (`env_literals`, never `env_names`).
`Patch.UnsetNames()` is the `unset` half; the host that creates the process
runs it against its own inherited environment (spec N9).

## 3. Binding, equality and the Record

### 3.1 Adapter identity

`adapter_identity = {adapter, harness, build, entrypoint}`, four strings. Two
identities are equal when all four are equal. The generic adapter reports
`adapter = "generic-env-v1"`; the caller fills `harness`, `build` and
`entrypoint` (the provider's `exec` fills `harness = "exec"`, `entrypoint =
the sanitized basename of argv[0] (see §5)`, `build = ""`).

### 3.2 Binding

`{profile_ref, profile_digest, adapter_identity, assurance, resolved_endpoint,
env_patch}`. `assurance` is `cooperative` in this version; a request for
`enforced` is refused (`network_scope_unsupported`). A managed gateway later
adds `lease_id` and `generation`.

### 3.3 Equality

Two bindings are **equal** iff `profile_digest`, `adapter_identity` and
`assurance` are equal. Excluded: `profile_ref` (names prove nothing),
`resolved_endpoint` (implied by the digest), `env_patch`, probe results and
their time, lease id, generation. An empty digest is never equal to anything.

### 3.4 Record

What run manifests and logs keep:

```text
{schema, profile_ref, profile_digest, adapter_identity{adapter, harness, build, entrypoint},
 assurance, origin, probe{tcp, connect, tls, checked_at}}
```

`origin` is `explicit`, `inherited`, `runtime-default`, `profile-binding`, `project-default` or
`operator-default`. N4 precedence is host locks / allowed set → explicit →
inherited → runtime-default → profile-binding → project-default → operator-default.
An inherited reference is supplied by the process owner, persisted from the
parent at reservation, and re-resolved on the child's host. It MUST NOT be
discovered from the environment or proxy values. `schema` MUST be `relux-network-binding-record-v1`
(`binding.SchemaRecord`, set by `Binding.Record`). Every listed field MUST be
present; `probe` MUST be a non-null object, including in plans and dry runs.
Each of `probe.tcp`, `probe.connect`, `probe.tls` is `ok`, `skipped` or `failed`;
`checked_at` is an RFC3339 timestamp. Plans and dry runs skip the preflight and
record all three steps as `skipped`, with their plan time. `Record(origin, nil)`
records all steps as `skipped` and the zero time `0001-01-01T00:00:00Z` for an
unobserved probe. Empty supplied statuses become `skipped`; unknown supplied
statuses become `failed`. The supplied probe is copied, so subsequent caller
mutation cannot change the Record.

A direct selection MUST produce the same managed Record with its actual named `profile_ref`, direct digest, selected origin and cooperative assurance. All probe steps are `skipped` on a real launch too; direct has no preflight endpoint.

An absent `network` key in a manifest = unmanaged. The Record MUST NOT carry
the environment, the patch, an endpoint or a credential.

### 3.5 Reattach and resume (spec N7)

`CheckReattach(recorded Record, fresh Binding, event, per_session_route)`:

| Event | Situation | Outcome |
| --- | --- | --- |
| `new-launch` | fresh process | `launch` |
| `new-assignment` | equal | `attach` |
| `new-assignment` | differs, adapter routes per session | `set-per-session` |
| `new-assignment` | differs, no per-session route | `network_scope_unsupported` |
| `reattach` | equal | `reattach` |
| `reattach` | same `profile_ref`, different `profile_digest` | `network_profile_drift` |
| `reattach` | any other difference | `network_scope_unsupported` (TODO(decision)) |

Missing or denied profiles are decided by resolve before this table.

The binding namespace uses exact lowercase `bindings`, `profiles` and reserved
`paths` keys. Case aliases and duplicate mappings are refused without merging;
quoted or escaped spellings must decode to these exact keys. Decode diagnostics
never echo unvalidated key metadata, including leaf-only duplicate errors.
See [the migration notes](../README.md#upgrading-for-operator-profile-bindings)
for source, strict CLI JSON decoder and hosted-carrier compatibility.


Host locks / allowed set constrain every selected reference. The reference
precedence is explicit → inherited → runtime-default → profile-binding →
project-default → operator-default. Empty or whitespace-only references do not select; all
selected references are trimmed before lookup. No selection is unmanaged.

An optional Curator profile name selects an operator-local default from
`[bindings.profiles]` in `~/.curator/network.toml`. Keys and network targets
MUST follow the profile identifier grammar; unknown keys are refused.
`[bindings.paths]` is reserved and MUST refuse with `network_scope_unsupported`,
even when empty. Bindings MUST NOT be read from a project or a Curator profile.
An omitted or unbound Curator profile adds no candidate. A selected binding to
an unknown network MUST refuse `network_profile_unknown` without fallback;
confirmation, assurance and allowed-set checks still apply. Bindings do not
change profile digests or binding equality. R5 shows the `profile-binding`
origin in a manifest-safe Record.

CLI `bind <curator-profile> <network>` and `unbind <curator-profile>` MUST use
the existing confirmation guard (no agent session, terminal stdin) and require
`yes` before writing. They prompt before acquiring the catalog edit lock,
recheck catalog bytes under that lock, and refuse intervening edits. Catalog
and backup writes use the existing atomic writer; the digest-confirmation
ledger is unchanged. Binding a target does not confirm its digest. Removing
a binding can expose a lower-priority default and requires the same guard.
CLI `list` includes all bindings; `show <network>` includes bindings to that
network. Both JSON documents add `bindings: {profiles: {...}}`; bind/unbind
success documents use `curator-network-bind-v1` / `curator-network-unbind-v1`,
`ok`, `curator_profile`, and optional `network` / `previous` strings. Unknown
bind targets and absent unbind entries use `network_profile_unknown`.
Unusual TOML edit layouts are refused with `network_profile_invalid` and a
manual-edit instruction, as with network profile removal.

The caller MUST supply the inherited reference it persisted from the parent
at reservation. The library MUST re-resolve it on the child's host, using
that host's catalog and digest-bound confirmation. It MUST NOT derive a
reference from proxy values or environment variables. Unknown inherited
references fail with `network_profile_unknown`; unconfirmed or disallowed
references fail with `network_profile_denied`, without falling back to any
default. The allowed-set check precedes existence, including for inheritance.

`allowed: null` permits any profile; `allowed: []` permits none. `confirmed`

## 4. Engine coverage (spec N12)

Direct has no proxy and nothing to bypass. The resolver MUST skip engine-host coverage for direct, while still enforcing allowed sets, confirmation and cooperative assurance.

A loopback engine host is **covered** by a profile iff `HostKey(host)` equals
`HostKey(entry)` for some `bypass_hosts` entry, where `HostKey` lowercases,
trims, removes a port when present and removes surrounding brackets
(`[::1]:11434`, `[::1]` and `::1` all become `::1`). Coverage is exact: a
suffix entry such as `.corp.invalid` or a CIDR does not cover by inclusion.
An uncovered engine host is `network_configuration_conflict`.

## 5. Refusal codes

The closed set. Every code is snake_case; the provider exits 1 on any of
them and prints `curator-network: <code>: <detail>`.

| Code | Meaning |
| --- | --- |
| `network_profile_unknown` | the selected profile is not in the catalog (or the catalog is absent) |
| `network_profile_denied` | outside the allowed set, or known but not confirmed at its current digest |
| `network_scope_unsupported` | `enforced` requested; a running host bound differently without a per-session route; a resume whose binding differs otherwise than by drift |
| `network_configuration_conflict` | an engine host is not in `bypass_hosts`; an edit that would conflict (existing name, operator default); a held catalog edit lock; catalog changed during confirm |
| `network_proxy_unreachable` | TCP failed or timed out, CONNECT non-2xx other than 407, or the TLS handshake failed |
| `network_proxy_auth_failed` | CONNECT answered 407 |
| `network_profile_drift` | resume of an existing run under the same profile name with a different digest |
| `network_profile_invalid` | malformed catalog content (addition, TODO(decision)) |
| `network_file_unreadable` | cannot read or write a catalog, backup or ledger; HOME unset; parse, encode, directory or lock creation failure (addition, TODO(decision)) |
| `network_confirm_refused` | `confirm` inside an agent session, without a terminal, or not answered `yes` (addition, TODO(decision)) |

Usage errors are not refusals (exit 2). In usage diagnostics,
operands and flag values are never echoed. This rule also covers the command
vector in dry runs and real-exec diagnostics. Only a sanitized entrypoint is
shown: `basename(argv[0])` when it passes the plain-subject rule
(`^[A-Za-z0-9][A-Za-z0-9._:-]{0,79}$`), otherwise `<command>`. The binding's
`adapter_identity.entrypoint` uses that same value. Human dry runs print
`would exec <entrypoint> (+N args)`, where N excludes the entrypoint. JSON dry
runs replace `command` with integer `argc` (including the entrypoint) and
sanitized `entrypoint`; no command arguments or entrypoint directory appear.
The flag package's own output is suppressed; diagnostics use fixed phrases
and registered flag names, such as `invalid value for flag -timeout`. A refusal
subject that fails the plain identifier rule becomes `<invalid name>` in
human and JSON errors.

A crash-stale `network.toml.lock` has no CLI cleanup. After checking no edit
is running, the operator deletes `network.toml.lock` by hand. TODO(decision):
whether to add a cleanup command.

CLI `add` clears any ledger entry for a new name before writing the catalog,
under the catalog edit lock; failure to clear it leaves the catalog untouched.
If the subsequent catalog write fails, that stale entry remains deleted.
An identical re-add always needs `confirm`. CLI `remove` of an absent profile
with a stale entry deletes the entry and exits 0 with a cleanup message
(`removed=false`, `confirmation_dropped=true` in JSON). A failed second write
in a normal removal leaves the catalog removal applied; retry `remove` after
correcting the ledger write failure to clean up the stale entry. With no catalog
and no stale entry, `remove` refuses without creating `.curator` or acquiring
an edit lock. Removing a confirmed operator default refuses with
`network_configuration_conflict`; catalog and ledger bytes stay unchanged.

CLI `confirm` prompts before taking the catalog edit lock (`network.toml.lock`,
O_CREATE|O_EXCL), shared with add/remove through `store.Edit`. After `yes`, it
holds that lock from re-reading the catalog and ledger through the atomic
ledger write. Contention refuses immediately with the same held-lock
`network_configuration_conflict` as add/remove. Any catalog byte change since
the preview, including comments, deletion or invalid TOML, refuses with
`network_configuration_conflict` and sanitized detail
`catalog changed during confirm; run confirm again`; the ledger is untouched.
The fresh ledger read preserves concurrent ledger edits made during the prompt.
The lock is released on success, refusal and write failure. Prompting first
avoids a human waiting or abandoning a terminal with a lock held, reducing the
risk of a crash-stale lock; an intervening edit or held lock may require the
operator to run confirm again after answering. Manual edits do not take this
advisory lock and must not race the locked read/write interval.

Unknown-key refusals report a count and, only for keys in one profile whose
name passes the plain-subject rule, `[networks.<name>]`. Unknown key names
and unsafe profile names are never echoed.

Unexpected internal failures map to `network_configuration_conflict` with the
fixed detail `internal operation failed` (TODO(decision)); no extra code is
emitted. TOML type and syntax errors expose fixed phrases and key/line metadata,
never decoder type names or content values.

### 5.1 Version JSON document

`--version --json`, `--json --version`, `-V --json` and `version --json` all
produce `curator-network-version-v1`. Its required fields are `schema` (that
literal), `ok` (true), `name` (`curator-network`), `version` (string), `revision`
(string), `dirty` (boolean), and `contract` (`relux-network-profiles-v1`).
